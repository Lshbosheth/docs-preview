# 模型路由：Agent 什么时候该换一个模型？

## 今天先记住

模型路由（model routing）是在每次模型调用前，根据任务阶段、输出约束、风险、延迟和预算选择模型，而不是整条 Agent 永远绑死一个“最强模型”或一个“最便宜模型”。关键不是模型排行榜，而是这次调用失败后，系统会走到哪个状态。

## 它在大地图里的位置

::: tip 今日坐标
**规划 / 决策 → ▶ 模型路由**
:::

```txt
用户目标
  -> 上下文 / 记忆
  -> ▶ 规划 / 决策
  -> 工具调用 / 外部系统
  -> 执行 / 观察结果
  -> 评估 / 修正
  -> 最终输出
```

前几天讲了审批、审计和补偿，重点是动作发生后的证据与收尾。今天往上游退一步：Agent 在决定“怎么做”之前，先要决定“用哪个模型做”。路由错了，后面的补救成本通常更高。

## 它到底是什么

模型路由可以很静态：某个节点固定调用小模型，另一个节点固定调用强模型。也可以很动态：根据输入长度、语言、是否要求 JSON、是否需要工具、数据敏感级别和历史失败率，选择模型、上下文、超时时间与回退策略。

路由器可以由规则、分类器或另一个模型实现，但它的输出必须可检查，至少包含 `route_id`、候选模型、选择理由、预算上限和失败后的下一状态。模型自己不能悄悄换目标，也不能因为一次超时就无限升级到更贵的调用。

## 为什么 Agent 里会用到它

Agent 一轮任务里常有不同性质的步骤：分类意图、抽取参数、制定计划、调用工具、总结结果和校验输出。分类和抽取通常需要稳定结构，计划需要处理歧义，最终写作需要语言质量，高风险动作则需要更强的工具调用准确性和失败识别。

如果全部交给同一个模型，常见结果是：简单结构化步骤浪费预算；复杂规划用弱模型时生成错误工具参数；调用失败后又靠重试碰运气。路由要解决的是这种“调用前匹配”，不是让模型显得更聪明。

## 怎么判断它有没有用

- 任务有明确的结构化输出和低风险时，可以路由到较便宜、较快的模型；如果输出错误会发送、发布、删除或付款，应优先保证参数和工具选择正确，并保留人工确认。
- 如果规则已经能确定下一步，不要为了“像 Agent”再让模型路由；只有输入变化大、模型能力差异明确、且路由结果可评估时，动态路由才值得做。
- 路由策略要按任务结果验收：schema 合法率、工具参数正确率、每成功一次任务的总成本、回退率和尾延迟，而不是只看模型通用跑分。
- 一个真实系统应能解释某次调用为什么选了这个模型，失败后是否回退、是否越权、是否重复产生副作用；只有最终答案不错，不足以证明路由可靠。

## 最近冒出来的词

LangChain 在 2026-09-17 发布 `langchain-typesafe==0.0.1a2`，其中包含实验性的 `ModelRouterMiddleware` 和 `TypeSafeClassifier`。它们目前属于 alpha 框架能力，不是生产标准；放在今天的主线里，它说明模型路由正从业务代码里的临时 `if/else`，尝试变成可复用中间件。真正要保留的仍是路由决策、类型约束和失败出口，而不是框架名字。

## 一个小例子

```txt
Input:
用户说：“检查今天的课程，合规后提交并推送。”

Process:
1. scan_request 由确定性规则读取文件，并生成待检查内容哈希。
2. risk_review 路由到适合结构化判断的模型，要求只返回 findings 和 severity。
3. 如果 severity 为 high 或输出 schema 不合法，路由到更强模型复核一次；仍不确定则进入 human_review。
4. commit 和 push 参数由程序根据已批准快照生成，不再交给模型自由改写。

Output:
routed: deterministic_scan -> structured_review -> approved_or_human_review
只有复核结论为安全且审批快照匹配时，状态才进入 publish_started；
否则停在 publish_blocked，不会因为换过模型就绕过权限检查。
```

这个例子里，模型路由只决定“哪次理解由哪个模型完成”，没有资格决定“是否允许推送”。这是它和权限、审批系统之间最该守住的分工。

## 常见误区

1. 把模型路由当成自动挑选排行榜第一名；实际应按当前任务的失败后果和输出约束选。
2. 让模型自由切换工具、预算和权限；路由只能提出候选，执行策略仍应能拒绝。
3. 只统计平均成本，不记录失败重试、回退和重复调用，最后看不到真实总代价。
4. 每次失败都无上限升级模型，形成一个慢、贵且无法复现的循环。

## 今天自测

1. 你的 Agent 里，哪些步骤其实不需要模型，哪些步骤一换模型就会改变风险？
2. 一次路由决策至少要记录哪些字段，才能在排障时还原选择？
3. 当便宜模型输出坏 JSON 时，你会回退、拒绝还是询问用户？边界由谁决定？
