## 人话意思

第一句是在说：只要一个函数前面写了 <Pronounce text="async" />，它返回给外面的东西一定是 <Pronounce text="a promise" />。

第二句是在补充：哪怕你在函数里直接 <Pronounce text="return one" />，外面拿到的也不是普通数字，而是一个被自动包起来的 <Pronounce text="promise" />。

这里的重点不是背语法，而是以后看到报错或类型提示时，别被 <Pronounce text="Promise" /> 吓一跳：它经常只是 <Pronounce text="async" /> 带来的正常结果。

## 关键词

- <Pronounce text="async function" />: 异步函数；通常用来写需要等待结果的逻辑
- <Pronounce text="return a promise" />: 返回一个 Promise
- <Pronounce text="return value" />: 返回值
- <Pronounce text="explicitly" />: 明确地；代码里直接写出来
- <Pronounce text="implicitly" />: 隐式地；代码没明写，但运行机制会自动做
- <Pronounce text="wrapped in a promise" />: 被包进一个 Promise 里

## 句子拆解

先看短句：

<Pronounce text="Async functions always return a promise." />

主语是：

<Pronounce text="Async functions" />

动作是：

<Pronounce text="return" />

宾语是：

<Pronounce text="a promise" />

所以这句可以直接压成一个技术判断：<Pronounce text="A returns B." />，意思是“某个东西返回某个结果”。

再看长一点的条件句：

<Pronounce text="If the return value of an async function is not explicitly a promise, it will be implicitly wrapped in a promise." />

前半句：

<Pronounce text="If the return value is not explicitly a promise" />

意思是“如果返回值本身没有明确写成 Promise”。

后半句：

<Pronounce text="it will be implicitly wrapped in a promise" />

意思是“它会被隐式地包进 Promise 里”。

这里 <Pronounce text="explicitly" /> 和 <Pronounce text="implicitly" /> 是一对很常见的技术文档词。文档说 <Pronounce text="explicitly" />，通常是在强调“你手动写出来”；说 <Pronounce text="implicitly" />，通常是在强调“系统或语言机制自动处理”。
