# Phase 4：Agent Handoff 草稿与人工闭环

## 阶段结果

Bridge 能把当前对话、已确认记忆和用户目标整理成可检查的任务卡或 Handoff JSON。第一版由用户或管理员复制给外部 Agent，并可把执行结果人工带回微信；本期不自动外发真实上下文。

协议以 [Agent Handoff Protocol](/personal-context-layer/handoff-protocol) 为准。

## 前置条件

- Phase 2 的记忆具有来源、状态和敏感等级。
- Phase 3 能把任务卡和带回结果总结成人话。
- 已定义 Handoff 请求、事件和审计的版本兼容策略。

## 最小状态机

```text
draft -> ready -> exported -> running_external -> result_received -> completed
   \-> cancelled        \-> failed
```

人工流程允许管理员或用户更新 `running_external` 和 `result_received`，但每次变化必须留下审计事件。

## 工作包

### P4-01：意图与目标确认

- 区分普通聊天、记忆更新、项目讨论和 `agent_handoff`。
- 从对话抽取目标、约束、期望产物和未决问题。
- 目标或工作区不明确时先澄清，不生成看似可执行但范围含糊的任务。
- 高风险动作只写入“需确认事项”，不默认为已授权。

### P4-02：Context Package Builder

生成可预览的 `ContextPackage`，至少区分：

```text
用户当前请求
必要会话摘要
用户 / 项目记忆引用
已确认约束和决策
期望输出
未解决问题
敏感项占位和披露建议
```

本期只从允许的本地数据构建草稿，不把未确认候选记忆当成事实。

### P4-03：Handoff Request 与事件

- 请求包含协议版本、目标 Agent、目标、Context Package、权限声明和关联会话。
- 事件使用稳定 ID、请求 ID、时间、动作人和前后状态。
- 创建、编辑、导出、取消、带回结果和总结均写入审计。
- 重复提交同一个动作保持幂等，不产生两份外部任务记录。

### P4-04：任务卡预览与导出

- 支持后台预览、复制 Markdown / JSON 和下载任务卡。
- 清楚标出来源、缺失信息、敏感占位和需要人工确认的内容。
- 导出前允许移除不必要上下文；编辑不反写原始记忆。
- 导出文件不包含令牌、连接串或内部日志。

### P4-05：人工结果带回

- 管理员可粘贴外部 Agent 结果或上传结果文件。
- 结果关联原 Handoff，并保留“外部报告”与“Bridge 验证结果”的区别。
- 人话总结说明完成项、未完成项、风险和下一步。
- 未验证的外部结果不能自动改写成“已经成功”。

## 验收清单

- [ ] 从真实项目对话生成结构完整、范围清楚的 Handoff 草稿。
- [ ] Context Package 中每条记忆都能追溯来源和当前状态。
- [ ] 未确认候选和高敏内容不会被静默导出。
- [ ] 用户可以在导出前查看、删减并取消任务卡。
- [ ] 重复点击导出或带回结果不产生重复 Handoff 终态。
- [ ] 外部结果带回后，微信收到简明总结并能继续追问。
- [ ] 所有状态变化在 Handoff Audit 中可重建。
- [ ] 整个闭环不要求 Bridge 执行 shell、文件修改或 Git 操作。

## 不在本期做

- 自动调用真实 Codex / Qwen Code / Claude Code。
- 把 Context Package 自动发送到外部服务。
- 多 Agent 自动调度、竞价或结果投票。
- 以导出任务卡代表用户已经授权其中的高风险动作。

## 发布与回滚

功能默认只对后台允许名单开放。关闭开关后停止新建和导出，已有 Handoff 仍可只读查看和人工完成；协议数据只追加事件，不通过回滚删除审计。
