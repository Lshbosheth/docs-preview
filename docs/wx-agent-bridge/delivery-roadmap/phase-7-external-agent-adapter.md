# Phase 7：外部 Agent 适配与自动闭环

## 阶段结果

在披露策略和用户授权之下，一个真实外部 Agent 能接收 Handoff、持续回报状态、返回结构化结果，并由 Bridge 在微信中给出准确的人话总结。

先完成一个适配器的生产级闭环，再扩展 Codex、Qwen Code、Claude Code 等更多目标；不要一开始同时维护多套半成品协议。

## 前置条件

- Phase 4 的 Handoff 状态机和人工闭环稳定。
- Phase 5 的披露策略强制执行，所有真实外发均可审计。
- Phase 1 的队列、回复、超时和恢复能力已经通过兼容门禁。
- 已选择首个适配器并明确认证、并发、超时、取消和数据保留边界。

## 适配器边界

统一接口至少包含：

```text
capabilities()
submit(HandoffRequest)
status(externalTaskId)
events(cursor)
cancel(externalTaskId)
result(externalTaskId)
health()
```

目标 Agent 的特殊字段留在适配器内部，核心 Handoff 协议不绑定某个厂商事件格式。

## 工作包

### P7-01：能力协商和目标选择

- 记录适配器版本、可用模型、支持输入/附件、取消能力和最大任务时长。
- Handoff 创建前校验目标能力，不支持时明确失败或退回人工导出。
- 目标选择先使用可解释规则，不做不透明多 Agent 自动调度。

### P7-02：提交幂等与任务关联

- 本地 Handoff ID 与外部任务 ID 一一关联。
- 提交请求带幂等键；超时后先查询再决定是否重试。
- 只在 Context Disclosure 通过后构造最终外发包。
- 认证信息由适配器安全加载，不进入 Context Package。

### P7-03：事件、状态和进度

- 将外部状态映射到统一 Handoff 状态，保留原事件引用。
- 事件使用游标去重并可重放；乱序事件不会让终态倒退。
- 进度消息节流，只在真实状态变化或用户主动查询时发送。
- 连接断开不等于任务失败，先查询真实外部状态。

### P7-04：结果、附件和验证

- 结构化保存总结、产物、警告、失败原因和未完成项。
- 图片或文件成功回传即视为有效结果，不追加空响应。
- 区分 Agent 声称完成、Bridge 可验证完成和用户确认完成。
- 结果过大时保存引用并在微信给摘要，不截断关键失败信息。

### P7-05：取消、恢复和降级

- 用户取消先记录意图，再调用外部取消并确认实际状态。
- Bridge 重启后从持久化游标恢复，不重复提交任务。
- 适配器不可用时可退回 Phase 4 人工任务卡，不阻塞普通聊天。
- 外部任务已运行但状态暂不可查时，回复“正在确认”，不能误报失败或完成。

### P7-06：首个适配器灰度

- 使用内部允许名单和低风险任务。
- 限制并发、上下文大小、附件类型和最长运行时间。
- 对比人工任务卡流程的成功率、时延、上下文质量和错误率。
- 观察期通过后再扩大用户、项目和任务类型。

## 验收清单

- [ ] 同一 Handoff 在提交超时和重启后不会创建两个外部任务。
- [ ] 外部断连时能查询真实状态，不把断连直接等同失败。
- [ ] 乱序和重复事件不会让终态倒退或产生重复微信通知。
- [ ] 披露被拒绝时不会调用适配器，也不会记录虚假的外部任务 ID。
- [ ] 任务取消、取消失败和取消太晚具有不同用户反馈。
- [ ] 图片 / 文件结果可送达且不追加空响应。
- [ ] 适配器不可用时普通聊天正常，Handoff 可降级为人工导出。
- [ ] 从提交、披露、外部事件到微信总结可用同一审计链重建。
- [ ] 小流量观察期没有高风险停止条件后才扩大范围。

## 不在本期做

- 同时开发所有 Agent 适配器。
- 自动把同一任务广播给多个 Agent。
- Bridge 自行执行外部 Agent 要求的本地高风险操作。
- 用无限重试掩盖外部服务长期不可用。

## 发布与回滚

适配器按目标和任务类型分别开关。回滚时停止新自动提交，保留对在途任务的只读状态同步；必要时转人工跟进，不能简单遗忘已经提交的外部任务。
