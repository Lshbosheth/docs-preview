# Phase 2：Memory MVP

## 阶段结果

系统能在用户允许的范围内记住稳定偏好、会话事项和项目事实，并能说明“记住了什么、从哪里来的、为何这次用了它”；错误记忆可纠正、删除或停用。

## 前置条件

- Phase 1 的会话、消息和回复记录稳定，`userId`、`chatId`、`threadId` 关联明确。
- 已确定数据保留周期、敏感字段分类和删除路径。
- 没有把原始全部聊天直接当成长期记忆。

## 记忆分层

```text
Session Memory      当前会话临时上下文
User Memory         稳定偏好与用户明确事实
Project Memory      项目目标、术语、约束和已确认决策
Runtime Summary     外部 Agent 最近任务的简明状态和结果
Memory Candidate    尚未确认或置信度不足的候选
```

每条长期记忆至少包含类型、内容、来源消息、创建方式、置信度、敏感等级、状态、创建/更新时间和最后使用时间。

## 工作包

### P2-01：存储与生命周期

- 定义候选、有效、冲突、已撤销、过期状态。
- 原始会话、记忆和审计分别设置保留策略。
- 删除用户或项目记忆时同步清理检索索引和缓存。
- 数据迁移可向后读取，回滚不丢原始来源。

### P2-02：候选提取

- 只从明确陈述、重复稳定偏好或已确认项目决策产生候选。
- 密钥、一次性验证码、临时错误和未经确认的模型推断不得成为长期记忆。
- 候选记录证据和置信度；不确定内容保持候选态。
- 提取失败不阻塞正常回复。

### P2-03：冲突、纠正和遗忘

- 新旧事实冲突时不静默覆盖，保留冲突关系和决策记录。
- 用户明确纠正拥有最高优先级，并可以查看生效结果。
- 支持按单条、类型、项目和用户范围删除或暂停注入。
- 过期内容自动降权，但删除和归档语义分开。

### P2-04：检索和注入预算

- 先按用户、项目、类型和权限过滤，再进行相关性排序。
- 限制记忆条数和 token 预算，保留来源引用。
- 当前明确指令优先于历史偏好，项目约束优先于泛化猜测。
- 检索不可用时降级为会话上下文，不应导致整轮失败。

### P2-05：审计和管理能力

- 能查看记忆内容、来源、使用次数、最近使用、状态和敏感等级。
- 记录创建、确认、编辑、冲突、注入、披露、删除动作。
- 管理动作有操作者和理由，删除操作有可验证结果。

## 验收清单

- [ ] 用户明确说“以后回复短一点”后，后续会话能遵循并展示来源。
- [ ] 一次性临时信息不会自动成为长期记忆。
- [ ] 用户纠正错误项目事实后，新回复不再注入旧事实。
- [ ] 删除一条记忆后，存储、检索缓存和后续 Context Package 均不再包含它。
- [ ] 两条冲突事实不会被模型静默合并成一个错误结论。
- [ ] 检索服务异常时仍能完成不依赖长期记忆的普通回复。
- [ ] 注入日志只记录记忆 ID 和必要摘要，不复制敏感全文。
- [ ] 可以关闭某个用户或项目的长期记忆功能。

## 不在本期做

- 向量数据库和复杂知识图谱。
- 从所有历史聊天批量自动抽取长期记忆。
- 跨用户共享私人记忆。
- 使用记忆自动授权工具或高风险操作。

## 发布与回滚

先以“只提取候选、不注入”运行，人工抽样验证后再对允许名单启用只读注入；最后才启用自动确认的低敏稳定偏好。回滚时关闭注入和候选提取，保留可审计数据，不删除原始对话。
