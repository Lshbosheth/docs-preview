# Phase 3.5：Proactive Loop 主动链路

## 阶段结果

Bridge 不再只能等待用户发消息。它能从明确提醒、近期对话、未闭环事项和允许的互动策略中生成主动行动候选，在合适的时间重新核对最新状态，再决定发送提醒、进行跟进、发起问候、转成交互式任务卡或静默跳过。

本期的核心闭环是：

```text
近期对话 / OpenLoop / 明确提醒 / 互动策略
  -> 主动行动候选
  -> 过滤、排序和时间窗规划
  -> 持久化调度
  -> 到点读取最新上下文并复核
  -> 发送 / 延期 / 跳过 / 请求确认
  -> 根据用户回应和新事件回写状态
```

主动不等于擅自行动。模型可以提出候选和生成文案，调度、权限、幂等、静默时段和发送预算必须由确定性规则控制。

## 前置条件

- Phase 1 能可靠发送 unsolicited message，并保证重启、重试和恢复时不重复发送。
- Phase 2 能提供带来源、状态、有效期和置信度的记忆及 `OpenLoop`。
- Phase 3 能生成符合人设但不伪造状态的提醒、跟进和问候。
- 所有时间统一存储为带时区时间，用户侧默认按 `Asia/Shanghai` 解释。

## 能力分层

### 1. 确定提醒

用户明确给出内容和时间，例如“明天 10 点提醒我提交周报”。这类请求直接生成计划任务，不经过夜间模型猜测；时间有歧义时先确认。

### 2. 上下文跟进

从仍有效的 `OpenLoop`、近期会话和任务结果中提出候选，例如稍后询问身体是否缓解、第二天确认待办是否完成、试运行一周后复查结果。候选必须保留证据，低置信或高打扰项不自动排期。

### 3. 主动互动

问候、轻聊天和允许范围内的内容分享只在配置的时间窗内抽样触发。随机只决定“允许窗口内是否触发”，不能绕过静默时段、冷却时间、每日预算、当前状态和用户关闭开关。

### 4. 自动执行

第一版只允许发送消息、生成草稿、读取允许的本地状态等可回滚或无副作用动作。涉及外部写入、付款、发布、删除、代码修改、命令执行或向外部 Agent 披露上下文时，必须进入 Handoff / 权限确认，不得由本期静默授权。

## 数据边界

`OpenLoop` 表示“有件事尚未闭环”，不等于“应该在某个时间主动联系用户”。两者必须分开存储，避免每条临时状态都变成通知。

### ProactiveCandidate

```text
id

source_refs           message / open_loop / task / policy

```

### ScheduledAction

```text
id
candidate_id
session_key
action_type
due_at / window_start / window_end
timezone
payload_template
permission_level
dedupe_key
max_attempts
status
last_evaluated_at
decision_reason

```

候选是推断结果，任务是经过策略允许的执行计划。候选被拒绝、过期或来源已闭环时，不得继续生成任务。

## 状态机

```text
proposed -> scheduled -> due -> evaluating -> sent -> acknowledged -> completed
    \-> rejected       \-> deferred       \-> cancelled
                       \-> skipped         \-> expired
                       \-> failed -> retry_wait -> evaluating
```

- `sent` 只表示微信发送成功，不表示用户已经看到或事情已经完成。
- 用户回复“做完了、不用了、晚点再说”等内容时，关联任务和来源 `OpenLoop` 分别进入完成、取消或延期状态。
- 新消息已经证明状态变化时，到点任务应在 `evaluating` 阶段静默跳过，并记录原因。
- 终态不能因乱序事件倒退；重复触发使用 `dedupe_key` 保持幂等。

## 生成与调度策略

### 即时路径

明确时间提醒、刚产生的强跟进信号和用户主动配置变更在当前 turn 后生成或更新任务，不等待夜间批处理。

### 每日规划路径

每天在配置时间扫描近期会话、有效 `OpenLoop`、已有任务和用户日历边界，生成“今天可能值得做”的候选。规划器只产出候选，不直接发送消息；相同来源和目的必须合并。

### 到点复核

每个任务到点后重新读取：

```text
来源是否仍有效
用户是否已经完成、取消或延期
当前是否处于睡眠、通勤、会议等不宜打扰状态
近期是否正在对话或刚收到同类消息
是否超过静默时段、冷却时间和每日预算
权限和披露范围是否仍允许
```

任何一项无法可靠判断时，优先延期、请求确认或静默跳过，不能拿旧上下文硬发。

## 工作包

### P3.5-01：契约、存储和事件

- 固化 `ProactiveCandidate`、`ScheduledAction`、状态机和审计事件 schema。
- 所有候选保留来源、理由、置信度、有效期和生成版本。
- 任务创建、更新、认领、发送和终态写入同一持久化事实源。
- 使用稳定 `dedupe_key`，进程重启和队列重放不能产生双消息。

### P3.5-02：候选生成与合并

- 支持明确提醒的确定性解析和歧义确认。
- 从近期对话、有效 `OpenLoop` 和任务结果生成跟进候选。
- 合并相同目的的重复候选，过滤已完成、过期、低价值和纯瞬时状态。
- 模型输出必须通过 schema 校验和本地策略，提取失败不影响正常聊天。

### P3.5-03：持久化调度器

- 支持准确时间、时间窗、延期、取消、有限重试和进程重启恢复。
- 多实例使用租约或原子认领，同一任务只能有一个执行者。
- 处理系统休眠或服务停机造成的错过任务，按策略补发、重排或过期，禁止集中补发消息洪峰。
- 调度器只产生到期事件，不直接绕过评估器发送。

### P3.5-04：到点评估与权限

- 使用最新会话、来源状态、静默策略、冷却和发送预算重新决策。
- 输出 `send / defer / skip / request_confirmation` 及可审计原因。
- 高风险或有外部副作用的动作转为确认或 Handoff，不自动执行。
- 评估模型不可用时，明确提醒走确定性兜底；推断型跟进和随机互动默认不发。

### P3.5-05：主动消息与反馈闭环

- 文案明确区分用户设置的提醒、系统根据上下文发起的跟进和普通问候。
- 微信发送成功后记录平台消息 ID；失败按错误类别和幂等策略处理。
- 从用户回复和后续事实识别完成、取消、延期、拒绝和偏好变化。
- 更新任务状态时同步提出来源 `OpenLoop` 的状态变更，但仍经过统一 writer 和证据校验。

### P3.5-06：互动策略与反打扰

- 支持总开关、分类开关、静默时段、工作日规则、每日上限和同类冷却。
- 用户忙碌、睡眠、通勤或正在连续对话时抑制非必要主动互动。
- 随机问候使用可测试的窗口抽样和稳定随机种子，不能靠高频轮询碰概率。
- 连续未回应时自动降频；用户明确拒绝后立即停用对应类别。

### P3.5-07：管理、观测和回放

- 后台可查看候选来源、计划时间、当前状态、最近决策和跳过原因。
- 支持批准、编辑、延期、取消、立即试发和按类别暂停。
- 指标至少覆盖候选接受率、准时率、跳过率、重复发送、用户拒绝率和每日触达量。
- 提供不真实发送的 dry-run / shadow 模式，能用历史时间线回放决策。

## 验收清单

- [ ] 用户设置明确提醒后，时间和文案正确，服务重启也只发送一次。
- [ ] “玩完一局后午睡”在用户已经睡醒上班后自动闭环或过期，不再作为待提醒事项。
- [ ] 用户已在新消息中说明完成的事项，到点跟进会静默跳过并记录证据。
- [ ] 推断型跟进能展示来源和理由，低置信候选不会自动发出。
- [ ] 随机问候严格遵守静默时段、每日上限、冷却和连续未回应降频。
- [ ] 多实例认领、队列重放、发送超时和进程重启均不产生重复消息。
- [ ] 微信发送失败不会被记录为已送达，重试耗尽后任务进入准确失败状态。
- [ ] 高风险或有外部副作用的动作只生成确认 / Handoff，不会静默执行。
- [ ] 用户可以关闭全部主动消息或单独关闭提醒、跟进和随机互动。
- [ ] shadow 回放覆盖跨天状态变化、错过时间窗、延期、取消和来源过期。

## 不在本期做

- 根据所有历史聊天批量创建提醒。
- 把每条 `OpenLoop` 自动变成主动任务。
- 未经确认执行 shell、改代码、发邮件、发布内容、付款或删除数据。
- 多 Agent 自主编排、长期目标自主分解或无限递归创建任务。
- 用随机问候伪装真实事件、虚构正在发生的状态或承诺系统无法完成的动作。

## 发布与回滚

按四级开关逐步放量：

```text
Level 0  shadow：只生成候选和决策，不创建任务、不发消息
Level 1  explicit：只执行用户明确设置的提醒
Level 2  follow-up：允许白名单会话的上下文跟进
Level 3  interaction：允许受预算和静默策略约束的主动互动
```

自动执行外部副作用不随本期放量。任一级出现重复发送、静默时段触达、状态过期仍发送或拒绝后继续触达，立即回退到上一级；关闭发送后保留任务和审计供排查，不删除历史。
