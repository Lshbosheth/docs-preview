# Phase 6：Admin Web 重排

## 阶段结果

后台围绕“对话、记忆、Handoff、配置、审计”组织，能够支持排障和运营，但后台故障不会让微信主链路停止。

## 前置条件

- Phase 1–5 的核心对象和状态已经稳定，避免 UI 反过来固化临时数据结构。
- 控制面与消息数据面有清晰边界。
- 管理员身份、只读和修改权限能够区分。

## 导航顺序

```text
1. Conversations
2. Memory
3. Handoff
4. Config
5. Audit
```

`Agent Tools`、`Tool Audit`、`Permission Rules` 降级为历史或高级入口，不占主导航；旧 Runtime 页面不继续扩展。

## 工作包

### P6-01：Conversations

- 按用户、会话、时间、状态和错误类别筛选。
- 展示入站、排队、Agent、附件发送和终态时间线。
- 能用 `traceId` 查看脱敏链路详情和各阶段耗时。
- 提供安全中断或新 thread 操作时，必须显示真实状态和二次确认。

### P6-02：Memory

- 查看记忆类型、来源、置信度、敏感等级、状态和最近使用。
- 支持确认候选、纠正、停用和删除，并显示影响范围。
- 冲突记忆并列呈现，不通过 UI 静默覆盖。
- 每个修改动作写入审计。

### P6-03：Handoff

- 查看 Context Package、披露决策、状态时间线和外部结果。
- 支持预览、逐项删减、确认、取消和人工带回结果。
- 清楚区分“任务卡已生成”“已导出”“外部 Agent 已完成”“已验证”。
- 不把后台按钮变成无审计的任意命令执行入口。

### P6-04：Config

- 配置按运行、模型、Persona、记忆、Handoff 和保留策略分组。
- 敏感值只显示是否配置，不回显明文。
- 配置变更有校验、版本、差异、操作者和回滚入口。
- 区分热更新和必须重启的配置；重启走恢复通知机制。

### P6-05：Audit 与运维视图

- 聚合记忆、披露、Handoff、恢复和管理员操作审计。
- 提供队列、错误、空结果、恢复、生图分段耗时和发送结果概览。
- 审计默认不可修改，导出前再次脱敏。
- 后台查询限流，不能拖慢微信处理数据库。

## 验收清单

- [ ] 管理员可以从一条微信消息追踪到最终文本或附件回复。
- [ ] 能分辨任务仍运行、已失败、已取消和恢复完成。
- [ ] 记忆修改、披露确认、Handoff 状态和配置变更均有审计。
- [ ] 后台不显示 token、密钥、完整调用栈或不必要私人正文。
- [ ] 关闭 Admin Web 或制造后台异常时，微信收发继续工作。
- [ ] 只读用户无法修改记忆、配置或 Handoff 状态。
- [ ] 高风险操作有确认、幂等和结果反馈，刷新页面不会重复执行。
- [ ] 旧 Runtime 页面被标记历史状态，主导航不再引导继续开发。

## 不在本期做

- 通用低代码平台。
- 完整多租户和商业化 RBAC。
- 在浏览器内暴露 shell 或任意工具执行。
- 让后台成为生产消息处理的同步依赖。

## 发布与回滚

新导航可通过前端开关逐页启用，API 保持向后兼容。出现性能或权限问题时关闭对应页面，不停止微信主链路；配置和审计数据不可因 UI 回滚而丢失。
