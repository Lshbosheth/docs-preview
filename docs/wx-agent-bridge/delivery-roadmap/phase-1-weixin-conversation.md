# Phase 1：微信入口与可靠会话

## 阶段结果

自研 Bridge 能稳定接收微信消息、按会话有序交给 Codex、可靠回传文本或附件，并达到替换当前 `cc-connect` 链路的可靠性门槛。

本期是 10 月前切换的关键路径，必须完整继承[现有链路兼容基线](/wx-agent-bridge/cc-connect-compatibility-baseline)。

## 前置条件

- Phase 0 的消息契约、状态机、幂等键和测试夹具已经验收。
- 能以回放或隔离账号测试 iLink，不与当前生产消费者抢消息。
- 当前链路的正常、排队、失败、生图、重启和恢复样本已留存。

## 工作包

### P1-01：iLink 单一入口

- 将登录、token 刷新、长轮询游标、拉取和发送隔离在适配器中。
- 单账号实施消费者租约或等价单实例保护。
- 拉取成功、处理成功和游标推进的边界明确，避免先确认后丢消息。
- 重连使用有上限的退避和抖动；鉴权失败与暂时网络失败分开处理。

### P1-02：消息归一化与持久化

- 支持文本、图片、文件、混合消息和纯附件。
- 保存原始事件引用、归一化结果、处理状态和必要附件元数据。
- 使用 `messageId` 去重，重复消息不重复调用 Agent。
- 先持久化“已接收”再进入执行；服务重启后可恢复未终态消息。

### P1-03：会话队列和上下文

- 同一 `chatId` 串行，不同会话在受控并发下并行。
- 队列有容量、等待时长和拒绝策略，不无限增长。
- 排队提示、队满提示和状态更新符合人设且去重。
- 最近对话按预算注入，避免 thread 无限膨胀；旧 thread 失效时可创建新 thread。

### P1-04：Codex 会话适配

- 启动请求始终包含有效用户消息；纯附件生成明确的附件上下文，避免 `Missing --message`。
- 解析结构化事件、文本、图片、文件、终态和异常关闭。
- app-server 连接关闭、thread 恢复失败和协议未知事件有不同错误分类。
- 空结果只在安全边界内有限重试；不得自动重放已执行的工具轮次。

### P1-05：统一回复终态

`ResponseEnvelope` 至少表达：

```text
text
artifacts[]
userVisibleStatus
terminalStatus
errorCategory
```

- 有文本、图片或文件任一成功送达，即视为本轮已有回复。
- 生图结果送达后禁止再追加“空响应”兜底。
- 同一入站消息最多发送一次终态兜底。
- 微信发送失败需要可重试且幂等，不能因为重试产生双回复。

### P1-06：超时、卡死和恢复

- 区分排队超时、Agent 启动超时、turn 超时、无事件超时和微信上传超时。
- 超时后先检查任务是否仍运行，再决定等待、提示、安全中断或失败。
- app-server 或 Agent 异常恢复成功后主动通知受影响会话。
- 计划内服务重启记录待通知会话，真实健康检查通过后再发送恢复消息。
- 恢复通知本身幂等，重启循环不能重复轰炸用户。

### P1-07：链路级可观测性

分段记录：

```text
微信拉取 -> 入队 -> Agent 启动 -> 推理 / 工具 -> gpt-image-2
         -> 结果解析 -> 微信上传 -> 用户可见终态
```

最少聚合：接收数、去重数、队列长度、各阶段耗时、空结果、附件结果、错误类别、恢复次数、回复发送结果。

## 关键验收场景

- [ ] 普通文本连续对话能承接最近上下文。
- [ ] 纯图片或文件没有正文时仍能进入 Agent，不报 `Missing --message`。
- [ ] Agent 只返回图片时，微信收到图片且没有后续空响应。
- [ ] 空结果有限重试；含副作用工具的 turn 不重放。
- [ ] 同一消息重复拉取、服务重启和发送重试均不产生双回复。
- [ ] 同一会话的第二条消息排队，不会打断第一条；不同会话不互相阻塞。
- [ ] app-server 异常关闭被转换为符合人设的失败或恢复提示，不暴露原始错误。
- [ ] 卡死 turn 能被发现、安全中断，并允许该会话处理后续消息。
- [ ] 旧 thread 失效后可以切新 thread，且用户得到准确说明。
- [ ] 计划重启和异常恢复只在链路真正健康后通知。
- [ ] 生图慢时能定位耗时属于推理、生图、解析还是微信上传。
- [ ] 当前链路兼容基线的自动和真实微信回归全部通过。

## 性能基线

Phase 1 的影子回放先测出当前链路与自研链路的 p50、p95 和最长耗时，再确认数字门槛。正式切换至少要求：

- 文本和附件成功率不低于当前链路同口径基线。
- 不出现已接收消息静默丢失、重复有效回复和基础设施错误泄漏。
- 队列等待、Agent 执行和上传耗时能够分别解释，不能只给一个总耗时。

## 不在本期做

- 长期记忆自动沉淀。
- 自动向多个外部 Agent 分发任务。
- 完整 Tool Runtime。
- 为提高速度而并行处理同一会话的多条消息。

## 发布与回滚

依次使用“历史事件回放 -> 影子处理但不回复 -> 允许名单单消费者 -> 小流量扩大”。任何双回复、消息丢失、错误状态承诺、附件后空响应或敏感信息泄漏都立即停止扩大并回滚，具体见[切换与回滚手册](./cutover-playbook)。
