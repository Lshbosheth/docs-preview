# Phase 0：方向收敛与工程地基

## 阶段结果

团队对产品边界、消息契约、故障语义、测试基线和部署边界使用同一套定义；后续开发不再从旧 Runtime / Tool Router 文档继续扩张。

## 前置条件

- [MVP 范围](/personal-context-layer/mvp-scope)已经确认。
- 当前生产链路的配置、启动方式、状态目录和恢复方式能够被盘点。
- 旧文档只读保留，不以“已经写过设计”为由默认进入新主线。

## 工作包

### P0-01：文档和决策源统一

- 把本目录设为交付主线，Personal Context Layer 文档设为产品定义。
- 将旧 Runtime、Tool Router、Day 10/11 文档标记为历史参考。
- 建立决策记录：问题、选择、理由、影响和撤销条件。
- 明确每期负责人、状态、依赖和完成证据的位置。

### P0-02：核心消息契约

至少固化以下对象及版本字段：

```text
InboundMessage
NormalizedMessage
ConversationTurn
ResponseEnvelope
ResponseArtifact
ErrorEnvelope
RecoveryEvent
```

契约必须支持文本为空但附件存在，区分业务文本、用户可见状态、图片和文件；未知字段可向前兼容，未知事件会记录和告警，而不是被静默丢弃。

### P0-03：状态机和幂等边界

推荐最小状态：

```text
received -> queued -> running -> replying -> completed
                             \-> failed
                             \-> cancelled
```

同时定义：

- 入站幂等键：平台 + 账号 + `messageId`。
- 回复幂等键：入站幂等键 + 回复版本。
- turn 和工具调用的关联键。
- 每个状态允许的下一状态、超时和恢复动作。
- “后台仍运行”和“已终止”的判定来源。

### P0-04：配置与环境边界

- 开发、回放、灰度、生产配置分离，密钥不进入代码库。
- 当前工作区的服务名、端口、数据目录、PID/锁文件和日志目录唯一。
- 启动前检查单实例和端口归属；停止操作只命中解析后的当前实例。
- 数据 schema 带版本，迁移采用“先扩展、后切换、再收缩”。

### P0-05：测试与观测地基

- 建立契约样本和消息回放夹具，覆盖文本、图片、文件、空文本附件和未知事件。
- 建立单元、集成、端到端、故障注入、迁移与兼容回归分层。
- 统一 `traceId`、错误分类、阶段耗时和脱敏规则。
- 为重复消费、队列积压、空响应、发送失败和进程恢复建立指标。

## 验收清单

- [ ] 新成员只读本目录和 Personal Context Layer 文档即可说清近期做与不做。
- [ ] 契约测试能解析文本、纯附件、图片结果和结构化错误样本。
- [ ] 同一消息重复投递时，状态机只创建一个有效处理记录。
- [ ] 未知事件会进入脱敏诊断和指标，不导致主循环退出。
- [ ] 日志扫描不包含 token、密钥或完整私人消息正文。
- [ ] 数据备份和恢复在非生产副本上演练成功。
- [ ] 当前工作区之外的服务和状态目录不会被启动、停止或迁移脚本命中。

## 不在本期做

- 真实生产切流。
- 长期记忆自动写入。
- 外部 Agent 自动 Handoff。
- 管理后台大规模重构。

## 发布与回滚

本期主要交付契约、测试和地基代码。所有新入口默认关闭；数据变更保持向后兼容。若新版本影响现有链路，关闭入口开关并退回旧读路径，不回滚已经安全写入的原始入站事件。
