# Phase 5：Context Disclosure Policy

## 阶段结果

系统在上下文离开 Bridge 前，能够按目标 Agent、用途、敏感等级和用户授权决定“可发送、需脱敏、需确认、禁止发送”，并留下可追溯审计。

策略定义以 [Context Disclosure Policy](/personal-context-layer/context-disclosure-policy) 和 [Handoff Permission Policy](/personal-context-layer/handoff-permission-policy) 为准。

## 前置条件

- Phase 4 的 Context Package 能标记每项内容的来源、用途和敏感等级。
- 外部 Agent 目标具有稳定身份、能力描述和数据处理边界。
- 能在真正发送前展示最终披露预览。

## 默认原则

```text
先拒绝，后允许
最小必要上下文
未知敏感等级按高敏处理
授权绑定目标、用途和本次 Handoff
日志记录引用，不复制秘密全文
```

## 工作包

### P5-01：上下文分类

至少覆盖：公开信息、内部普通信息、个人信息、项目敏感信息、凭据/密钥、高风险操作授权。分类结果包含规则版本和判定原因。

凭据、令牌、验证码和私钥默认禁止外发，不能通过普通确认降级成可发送内容。

### P5-02：策略决策点

- 输入目标 Agent、用途、Context Package 条目、用户授权和策略版本。
- 输出 `allow`、`redact`、`confirm`、`deny` 及原因代码。
- 策略不可用或分类未知时 fail closed，不自动放行。
- 决策逻辑独立于人话生成，不能被提示词覆盖。

### P5-03：裁剪与脱敏

- 先移除与任务无关内容，再对允许内容做字段级脱敏。
- 用户名、路径、项目名等是否保留由任务用途决定，不做一刀切。
- 脱敏后重新扫描，防止秘密出现在嵌套文本、附件元数据或错误堆栈。
- 最终发出的 Context Package 生成不可变摘要，供审计核对。

### P5-04：确认体验

- 清楚说明发送给谁、为什么需要、包含哪些类别、一次还是持续有效。
- 用户可以逐项移除、拒绝或仅允许本次。
- 范围、目标、用途或内容摘要变化后，旧确认失效。
- 超时或没有响应视为拒绝，不发送。

### P5-05：披露审计与撤销

- 记录策略版本、条目引用、决策、确认、目标、用途、发送结果和操作者。
- 审计界面默认隐藏秘密值，只显示类别、摘要和引用。
- 撤销影响未来请求；已发送内容不能伪装成“已从外部 Agent 删除”。
- 为误披露建立事件响应和通知流程。

## 验收清单

- [ ] 普通项目约束可按用途进入 Handoff，不带无关私人对话。
- [ ] token、验证码和私钥在任何普通流程中都不能外发。
- [ ] 高敏内容必须逐次确认，未响应和策略异常均拒绝。
- [ ] 用户修改目标 Agent 或任务用途后需要重新确认。
- [ ] 脱敏扫描覆盖文本、结构化字段、附件名和错误摘要。
- [ ] 每次实际披露都能从审计中解释“谁、向谁、为什么、发了哪些类别”。
- [ ] 日志和审计界面不包含秘密明文。
- [ ] 策略服务故障不会阻塞普通聊天，但会阻止自动 Handoff。

## 不在本期做

- 将普通确认作为 shell、Git 或生产变更授权。
- 承诺撤回已经交给外部系统的数据。
- 基于模型自由判断绕过确定性禁止规则。
- 跨用户共享上下文。

## 发布与回滚

先对 Phase 4 的导出预览运行“只评估不阻断”，比较人工判断；确认规则后启用强制阻断。回滚仅能收紧为“全部需人工导出”或“禁止自动外发”，不能退回无策略自动发送。
