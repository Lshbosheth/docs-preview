# 自研微信链路交付路线图

> 本目录是 `wx-agent-bridge` 的实施主线和交付事实来源。产品定位仍以 [Personal Context Layer](/personal-context-layer/) 为准；本目录负责回答“按什么顺序做、做到什么算完成、怎样切换和回滚”。

## 1. 北极星结果

在 10 月前具备安全替换当前 `微信 -> cc-connect -> Codex` 链路的能力，同时保留已经验证过的体验优化：

```text
微信 / iLink
  -> 单一消息入口
  -> 归一化、去重、按会话排队
  -> Conversation + Personal Context
  -> 意图判断
  -> 本地回答、主动链路或 Agent Handoff
  -> 人话总结
  -> 图片 / 文件 / 文本回复
```

替换成功不是“消息能转发”，而是以下结果同时成立：

- 已接收的消息不会无故丢失、重复执行或重复回复。
- 图片或文件已经送达时，不会再补一条空响应。
- 失败、排队、处理中、恢复完成具有真实且不同的用户语义。
- 底层进程、管道、URL、状态码和原始异常不会泄漏到微信。
- 记忆和交给外部 Agent 的上下文可解释、可删除、可审计。
- 关系核心始终常驻，按意图检索的记忆只补充事实和项目上下文，不能把关系定位或表达底色裁掉。
- 切换可灰度、可观测，并能在故障时快速退回当前链路。

## 2. 范围边界

主线负责：

```text
微信接入和回复
会话上下文
用户 / 会话 / 项目记忆
意图识别
Context Package
Agent Handoff
披露策略和审计
外部 Agent 结果的人话总结
提醒、跟进和受约束的主动互动
管理和运维视图
```

近期不负责：

```text
完整 Agent Runtime
通用 Tool Router
在 Bridge 内实现 write_file / run_command / git_push
复杂多 Agent 自动调度
向量数据库
多租户商业化权限体系
```

| [Phase 1](./phase-1-weixin-conversation) | 微信入口与可靠会话 | 能以兼容基线替换现有转发链路 | 未验收 |
| [Phase 2](./phase-2-memory-mvp) | Memory MVP | 记忆可追溯、可纠正、可关闭注入 | 未验收 |

| [Phase 3.5](./phase-3-5-proactive-loop) | Proactive Loop 主动链路 | 提醒、跟进和主动互动可调度、可复核、可关闭 | 未验收 |
| [Phase 4](./phase-4-handoff-draft) | Handoff 草稿与人工闭环 | 可生成任务卡并人工带回结果 | 未验收 |
| [Phase 5](./phase-5-context-disclosure) | Context Disclosure | 外发上下文先裁剪、脱敏、确认和审计 | 未验收 |
| [Phase 6](./phase-6-admin-web) | Admin Web 重排 | 对话、记忆、Handoff 和审计可运营 | 未验收 |
| [Phase 7](./phase-7-external-agent-adapter) | 外部 Agent 适配 | 一个真实 Agent 小流量自动闭环 | 未验收 |

推荐依赖顺序：

```text
Phase 0 -> Phase 1 -> Phase 2 -> Phase 3 -> Phase 3.5 -> Phase 4 -> Phase 5 -> Phase 7
                                      \------------------------------> Phase 6
```

`Phase 6` 可以和 `Phase 3.5–5` 并行，但后台不可成为微信回复或主动调度的数据面依赖。`Phase 7` 在 `Phase 5` 通过前不得自动向外部 Agent 发送真实上下文。

## 4. 每期统一工作方式

每一期按同一套步骤交付：

1. 确认范围和明确不做的内容。
2. 固化数据契约、状态机和失败语义。
3. 先补可自动执行的测试，再接生产入口。
4. 在脱敏日志中记录 `traceId`、`messageId`、会话标识、阶段、耗时和最终状态。
5. 使用功能开关或路由开关小流量启用。
6. 验证退出条件并附上测试、指标和人工验收证据。
7. 更新本页状态；未附证据不得标记“已完成”。

任务拆解统一使用 [工作项模板](./work-item-template)。

## 5. 全局交付门禁

### Gate A：消息正确性

- 同一微信账号只能有一个有效 iLink 消费者。
- `messageId` 幂等；同一入站消息最多产生一个有效终态回复。
- 同一会话保持顺序，不同会话可以并发。
- 纯附件可进入 Agent；附件成功送达即算有效回复。
- 有副作用的工具轮次不得因为空结果被自动重放。

### Gate B：故障与恢复

- 接收、排队、运行、已回复、失败、取消具有可区分状态。
- app-server 或 Agent 子进程异常时，先确认真实恢复，再通知用户。
- 卡死 turn 可以超时、判断状态并安全中断。
- 老 thread 无法恢复时可以切换新 thread，不阻塞整个微信会话。
- 任何失败路径都不得落成空响应或原始基础设施异常。

### Gate C：上下文安全

- 日志、错误回复模型和外部 Agent 都只获得完成目的所需的最少上下文。
- 常驻关系核心与按需事实检索分层：检索收窄、无命中或新建 thread 时，仍保留双方关系和表达底色。
- 记忆系统自身的技术问题只检索相关事件和源码，不得顺带注入宽泛项目段、无关生活事实或近期日报；项目修改类请求仍保留必要的近期摘要和源码核验。
- 密钥、令牌、连接串和未经允许的私人消息正文不得外发。
- 高敏上下文需要明确确认；未知分类默认不披露。
- 记忆和 Handoff 都有来源、目标、动作、时间和结果审计。

### Gate D：可运维性

- 文本、排队、错误恢复、生图、文件上传能分段记录耗时。
- 核心指标和错误类别可聚合，日志可用同一个 `traceId` 串联。
- 重启、迁移、回滚均有操作手册和结果通知。
- 管理后台不可用不影响微信入口继续处理。

### Gate E：切换安全

- 完整通过 [现有链路兼容基线](/wx-agent-bridge/cc-connect-compatibility-baseline)。
- 切换时不会启动两个会回复的消费者。
- 已验证备份、灰度、停止条件和回滚路径。
- 小流量稳定观察后才扩大范围，详见 [切换与回滚手册](./cutover-playbook)。

### Gate F：主动链路安全

- `OpenLoop`、主动候选和已排期任务分层存储，未闭环事项不会直接触发消息。
- 到点后必须读取最新状态复核；已完成、已取消、已过期或不宜打扰时静默跳过或延期。
- 静默时段、分类开关、冷却、每日预算和用户拒绝优先于模型建议。
- 调度认领和微信发送全链路幂等，重启、重试和多实例不产生重复触达。
- 任何外部副作用和敏感上下文披露仍受确认、Handoff 与审计约束。

## 6. 全局 Definition of Done

一个阶段只有同时满足以下条件才算完成：

- 范围内代码、迁移、配置和文档已经落库。
- 单元、集成、故障注入和相关兼容回归通过。
- 关键日志已脱敏，指标和告警能定位失败阶段。
- 旧数据和在途任务有明确处理方案。
- 功能可关闭或版本可回滚，且回滚不会破坏已有数据。
- 真实微信验收通过，没有空响应、重复回复和错误状态承诺。
- 新 thread、检索无命中和本地兜底场景均通过关系连续性与检索范围回归，不会退回通用助手或客服口吻。
- 主动任务通过时区、静默时段、到点复核、重启恢复和重复发送测试。
- 阶段文档记录测试证据、已知限制和遗留项。

## 8. 维护规则

- 本页只维护阶段、依赖、状态和全局门禁，不堆实现细节。
- 每期细节只写入对应阶段文档，跨阶段约束写入本页。
- 临时决策必须写明原因、影响和撤销条件；不能只留在聊天记录里。
- 旧 `Day N` 和 Runtime 文档保留作历史参考，不再作为排期依据。
- 路线变化时先更新本页，再调整 backlog 和实现提示词。
